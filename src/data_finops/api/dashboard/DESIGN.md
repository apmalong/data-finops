# Dashboard design note

Each rule of spec 06's Dashboard section, quoted as written (after Edward Tufte, *The Visual
Display of Quantitative Information*, and Stephen Few, *Information Dashboard Design*), then
how this dashboard meets it. `tests/integration/test_dashboard.py` fails if a rule is
missing, reworded or unticked. Review a change against this list and the screenshots in
`docs/implementation/screenshots/`.

- [x] One screen answers the first question at a glance: where did the bill of this period go? The Cost Summary is the overview. Details come on demand, through the Cost Explanation.
  The page leads with each currency's total and one chart of where it went; the Snapshot Scope and Cost Basis are the only filters. Four tabs (#313), Summary, Models, Runs and Cost Dimensions, show one section at a time, so the page does not scroll from one to the next; Summary opens first, and `#tab=<name>` reopens a tab (`#run=` opens Runs). Details open on demand under the charts (#118): any amount row lists the Allocations behind it, any Allocation opens its Cost Explanation (Billing Line, Allocation, Evidence nearest first, Roll-ups), and any Workload Run opens its lineage; `#explain=<ref>` and `#run=<id>` reopen them from a link.
- [x] Maximize the data-ink. Use no gauges, dials, pie or donut charts, 3-D, gradients, shadows, decorative icons or heavy gridlines. Each mark encodes data.
  No shadows anywhere, tooltip included; the only rule in a chart is its zero baseline; the one glyph, ⚠ beside a non-zero Reconciliation Delta, is a status cue, not decoration.
- [x] Use tables where exact amounts are important. Use right-aligned tabular figures at the scale of each line. State the currency one time in each column. Use light rules only between groups.
  Every chart has a table beneath it; amounts are the API's exact decimal strings; the currency is stated once, in the amount column's heading ("Amount, USD"), and once in each panel's heading.
- [x] To compare parts of the bill, use horizontal bars on a common zero baseline, sorted by amount. Label the bars directly, not through a legend. The parts are the amounts allocated by Confidence, Unallocated by reason, Adjustments and Roll-ups.
  One baseline per chart; positive amounts largest first, then negative ones (Adjustments, left of zero); each bar carries its exact amount and its label; no legend. A bar's amount has the currency symbol and the chart's number of decimals, padded with zeros so that the amounts line up, never rounded (#313). A label keeps its name on one line and its detail on the next, each cut with an ellipsis, never broken inside a word; an ID shows its first eight characters, and the title and the table keep it in full. A Workload Run is named by its job and start time (the API's `run` on each `workload_run` Roll-up).
- [x] By default, color is muted. Use it only to get attention: one highlight for amounts that require attention (Unallocated, a Reconciliation Delta that is not zero, failed runs). Never use color as decoration or as the only cue.
  Allocated amounts take one series hue; Unallocated amounts take the one highlight, and so do Adjustments, which are Unallocated amounts shown apart (OQ-18); a non-zero Reconciliation Delta is said in words beside its ⚠, and so is a Workload Run whose status is failed, aborted or conflicting (two terminal events disagree: it needs a reader as much as a failure does), always with the status written out. Both hues are the dataviz skill's validated steps (light `#2a78d6`/`#eb6834`, dark `#3987e5`/`#d95926`; every check passes in both modes).
- [x] Estimates look different from billed facts. Metered Shares show their Confidence and Coverage next to the amount (acceptance.md). Thus the reader never thinks that an estimate is an exact cost.
  Each allocated amount's detail names its Confidence and Coverage, for example "Direct · metered estimate, Coverage 1" (a range when lines differ).
- [x] Keep the placement and the terms consistent. Use only GLOSSARY terms (Unallocated, never "unknown"). The policy version, the Calculation Run and the Reconciliation Delta are always visible, but not prominent.
  The Calculation Run, its time and policy version sit under the title; each panel states its Reconciliation Delta beside its total.
- [x] Use small multiples when the same chart repeats across currencies or Cost Bases. Use shared scales in a currency, never across currencies.
  Each currency is its own panel with its own scale. Cost Bases are chosen one at a time, so each view shows one; Roll-ups are charted per currency for that Cost Basis.

Also: every opener (an amount's name, a Billing Line in an Allocation list, a run) is a real `<button>` inside its list item or table row, which keep their roles, with a visible focus ring; an amount with one Allocation opens its Cost Explanation directly; the detail panel is a polite live region, closes when the Snapshot Scope or Cost Basis changes, and follows the address (`#explain=`, `#run=`). The root Workload Runs are listed under the Roll-ups, so a run that carries no cost can still be opened. Light and dark each have their own validated steps; the page follows the system setting, and `data-theme` on `<html>` forces one. `forced-colors` keeps bars and the baseline visible. Each bar row is keyboard-focusable with an accessible name that leads with its amount.

Cost Dimensions (#223): one panel for each currency, as in the Cost Summary. Each value is a bar and a table row with its source. Unassigned takes the one highlight, because cost with no value needs a reader. The total row comes from the API (`totals`), so the dashboard never adds amounts. Without a configuration, the section says that none is configured. Screenshots: `docs/implementation/screenshots/223-dimensions.png` and `223-no-dimensions.png`.

The public demo (#228, spec 09): the same page and script, with `<meta name="data-finops-source" content="static">`. Then `static.js` answers each read from the Demo Snapshot's files, as the API answers it, and a read that the snapshot does not cover says so in the notice ("… is not in the public demo"). A banner above the title says what is simulated and what is real, when the snapshot was published, and its Calculation Run; it is the only addition, in the second ink (`--ink-2`) above a light rule, so the rules above hold unchanged. Screenshots: `docs/implementation/screenshots/228-static-demo.png` and `228-not-in-demo.png`.

Known limit: with a bearer token configured (ADR 0024) the dashboard, like every route, needs the `Authorization` header, which a browser does not send on its own; the token-free loopback demo is where it is used in M5.
