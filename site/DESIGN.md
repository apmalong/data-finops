# Site design note

Each rule of spec 07's "Design and writing" section, quoted as written, then how the site meets it. `tests/unit/test_site_design.py` fails if a rule is missing, reworded or unticked. Review every page against this list.

- [x] The dashboard's visual rules (spec 06): Tufte and Few, light and dark through `prefers-color-scheme`, a system font stack, muted colour used only to draw attention.
  `site.css` keeps the dashboard's muted palette: ink on the page, and `--attention` only on a `.notice` the reader must not miss. Links take one colour and are underlined in page text: the colour marks what can be followed, alongside the underline, and never draws attention or stands alone as a cue. Nav links are a plain list, with the current page in bold. Light and dark follow the system setting; `data-theme` on `<html>` forces one. The font stack is `system-ui`, so nothing is downloaded. Amount tables use right-aligned tabular figures and light rules.
- [x] `site.css` starts as a copy of the dashboard's tokens and evolves separately. Foreground and background token pairs reach at least 4.5:1 contrast in both themes.
  The page, surface, ink, rule and attention tokens are the dashboard's, renamed by role (`--bg-*`, `--text*`) so the checker can pair them. Two differ: `--text-3` is #6b6a65, because the dashboard's light `--ink-3` (#75746f) is 4.44:1 on the page; and `--link` (#1f5fae light, #6aa6ef dark) is new, because the dashboard's series blue (#2a78d6) is 4.19:1. `python -m scripts.site check` computes WCAG contrast for every text token (`--text*`, `--link*`) on every background token (`--bg-*`) in each theme block, with `:root` as the base every other block inherits. It reports `low-contrast` under 4.5:1 and `unchecked-colour` for a text or background value that is not a hex colour. Non-text tokens (`--rule`, `--attention`) are outside this text rule; `--attention` on the page is 3.04:1 in light, just over the 3:1 WCAG asks of non-text marks.
- [x] Readable: a 17px body, prose lines of at most about 68ch, a 1.6 line height, and a distinct heading scale with room above each `h2`.
  `site.css` sets `body` to 17px/1.6 and `p, li { max-width: 68ch }`. `h1` is 2.1rem, `h2` 1.45rem with 2.6rem above it, and `h3` 1.15rem. Code blocks wrap, and each line keeps a hanging indent, because `build` puts every line of a plain-text code block in a span. Wide tables scroll in their own box. The nav shows only the current section, and "On this page" and the previous and next links are stamped by `build` (spec 07, "Layout").
- [x] Accessible: `lang`, one `<h1>`, ordered headings, alt text on every image, visible focus, and the nav usable by keyboard. Pages work without JavaScript.
  The checker requires `lang`, one `<h1>`, alt text on every image and balanced tags. Every page starts with a skip link to `<main id="main">`, and `:focus-visible` draws a 2px ring in the link colour. The nav, "On this page" and the previous and next links are plain links, so they are keyboard-usable with no script. A wide table's scroll box takes focus and is a named region, so it can be scrolled by keyboard. The only JavaScript is `site.js`, which turns each command block's two versions into Windows and macOS/Linux tabs (#173). Its buttons use `aria-pressed`. Without it, both versions show, each labelled, so every page still works. Heading order is reviewed by eye.
- [x] No `http(s)://` in CSS or JS. Outbound links in page text are fine.
  The checker reports `external-url` for `http(s)://` or `//` in CSS and JS files, inline styles and scripts, and in any asset an element loads; outbound `<a>` links are allowed.
- [x] Diagrams are committed SVGs rendered from D2 sources in `docs/architecture/` (`d2 --layout elk`). There is no Mermaid.
  The explanation pages' diagrams have their D2 sources in `docs/architecture/` (`bill-to-roll-ups.d2`, `coverage.d2`) and their SVGs in `site/assets/explanation/`, rendered as `docs/architecture/README.md` lists. The checker requires each image to exist and have alt text. D2's light theme is used in both site themes, on a white panel.
- [x] Writing: glossary terms capitalised as in GLOSSARY, never their avoided synonyms. Short declarative sentences. Explanation pages cite their ADRs and specs, which stay authoritative. The only account ID is the placeholder `123456789012`. No real account IDs, bucket names, credentials or SQL literals appear.
  Reviewed for each page against GLOSSARY.md. The checker reports `account-id` for any 12-digit number other than `123456789012`, without echoing it.
