Exit codes and environment

This page lists the exit codes of the data-finops command and the environment variables data-finops reads. A test checks both lists against the code.

Exit codes

Every data-finops command exits with one of these codes.

0
Everything was stored. For serve and demo, the server stopped normally.
1
Something was rejected, and the rest was stored. Each rejected item is named by its position and the reason, never by its content.
2
Nothing was done. The arguments were wrong, a file could not be read or written, the database is not a data-finops database, or serve refused to start. The message says why.

Asking for help with --help exits with 0.

Environment variables

DATA_FINOPS_TOKEN

The bearer token for serve. When a token is set, every route, the API documentation included, needs the header Authorization: Bearer <token>. Without one, every route is open.

  • Set the token in this variable or in a file named by --token-file, not both. If both are set, serve exits with 2.
  • The token must be at least 16 characters, not counting surrounding spaces and line breaks, which are removed. A shorter token makes serve exit with 2.
  • serve needs a token to listen on an address other than loopback, such as --host 0.0.0.0. A name such as localhost does not count as loopback.
  • demo ignores the token. It always serves on loopback, with every route open.
  • data-finops never logs, prints or stores the token. Errors say what is wrong with it, not what it is.
DATA_FINOPS_ANON_SECRET

The secret for scripts/anonymize_focus_export.py, the script that anonymizes a downloaded AWS FOCUS export. The script is for contributors and is not part of the data-finops command.

  • The secret keys the pseudonyms. The same secret gives the same pseudonyms, so joins and grouping still work across runs.
  • It must not be empty. If it is empty or unset, the script stops before writing anything.
  • Keep it, and never commit it.
