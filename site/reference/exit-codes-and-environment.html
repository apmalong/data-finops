Exit codes and environment

On this page

  • Exit codes
  • Environment variables

This page lists the exit codes of the data-finops command and the environment variables data-finops reads. A test checks both lists against the code.

Exit codes

Every data-finops command exits with one of these codes.

0
Everything was stored. OpenLineage events of a kind data-finops does not read are listed as unsupported, and they do not change the code. For serve and demo, 0 means the server stopped normally.
1
A workload input was rejected, in whole or in part. Only ingest openlineage, ingest dbt and ingest athena exit with 1. If some items were rejected, the rest were stored. Each rejected item is named by its position and the reason. If the whole file was rejected, nothing was stored, and the message gives the reason. Messages never quote the input's content.
2
Nothing was done, and the message says why. These are the causes:
  • The arguments were wrong.
  • A file could not be read or written.
  • calculate or serve was given a --db path with no database file there.
  • The database file is not a data-finops database.
  • A FOCUS file is not a FOCUS Export Snapshot or a usable AWS Data Exports Delivery.
  • serve refused to start, for example because of the token rules below.

Asking for help with --help exits with 0.

Environment variables

DATA_FINOPS_TOKEN

The bearer token for serve. When a token is set, every route, the API documentation included, needs the header Authorization: Bearer <token>. Without one, every route is open.

  • Set the token in this variable or in a file named by --token-file, not both. If both are set, serve exits with 2.
  • Surrounding spaces and line breaks are removed from the token. What remains must be at least 16 characters. A shorter token makes serve exit with 2.
  • serve needs a token to listen on an address other than loopback, such as --host 0.0.0.0. A name such as localhost does not count as loopback.
  • demo ignores the token. It always serves on loopback, with every route open.
  • data-finops never logs, prints or stores the token. Errors say what is wrong with it, not what it is.
DATA_FINOPS_ANON_SECRET

The secret for the two anonymizing scripts. They are for contributors and are not part of the data-finops command.

  • scripts/anonymize_focus_export.py anonymizes a downloaded AWS FOCUS export.
  • scripts/anonymize_workload_outputs.py anonymizes the reference workload's Athena history, dbt artifacts and OpenLineage events.

The rules for the secret:

  • The secret keys the pseudonyms. The same secret always gives the same pseudonym for the same value. Use one secret for both scripts, so billing and workload data still match after anonymizing.
  • It must not be empty. If it is empty or unset, the script stops before writing anything.
  • Keep it, and never commit it.
