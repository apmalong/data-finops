Deployment architecture

On this page

  • Two functions and one bucket
  • Pulled, not pushed
  • Trust boundaries
  • What it costs
  • Limits to watch

A Deployment runs data-finops in one AWS account. It has no servers to operate and no network to manage. This page explains its parts, its trust boundaries and its cost. The decisions are in ADR 0026, ADR 0027 and ADR 0028. The design is in spec 08. These documents stay authoritative.

Two functions and one bucket

data-finops keeps all its data in one SQLite file, and only one writer writes to it at a time. A Deployment keeps that design. It does not add a database server:

  • The database is one S3 object, database/data-finops.sqlite, in the Deployment's private bucket.
  • The collector is the only writer. One time each day, it downloads the object, runs one Collection Run and uploads the result. It uploads only if the object is still the object that it downloaded (an S3 conditional write on its ETag). If a different write occurs at the same time, the upload fails, so the other write is not lost. The next run starts again from the current object.
  • The API only reads. It serves the object the last run wrote, never a half-written one, and downloads it again only when its ETag changes.

Neither function runs in a VPC, so there is no NAT gateway, subnet or endpoint to pay for or secure. Both reach S3, Athena and CloudWatch through AWS's public endpoints, signed with their own roles.

Pulled, not pushed

Locally, OpenLineage events can arrive over HTTP with a bearer token. A Deployment has no such endpoint, for two reasons. The token is local to prevent one risk: a long-lived shared token on a public URL. Also, standard OpenLineage clients cannot sign requests for a URL that IAM authorizes.

Thus producers write files to the Inbox, with an IAM policy that permits nothing else. The next Collection Run pulls the new files. Thus lineage arrives one time each day. That is also when data-finops calculates costs. See Send workload metadata to the Inbox.

Trust boundaries

  • The account. The FOCUS export, the Athena workgroups and the Deployment are in one account, and so are the IAM principals of its producers and readers. Nothing crosses into another account.
  • The Function URL. It is reachable from the internet. But AWS rejects a request before the function runs if the signer does not have permission to invoke the function. A principal with the reader policy has this permission. The API mounts only the read endpoints, so there is no write route to reach.
  • Producers. A producer can put objects in the Inbox and do nothing else: not read them back, list them or touch the database. What it writes is screened like any input: each event capped at 1 MiB, each file at 512 MiB, and a rejected file reported by its key and reason, never its content.
  • The collector's reach. It reads the export, the Athena history of the configured workgroups and the Inbox, and writes only the database object. It cannot run queries or read their results, which an explicit deny enforces. Query text is dropped before anything is stored.
  • The bucket. The bucket blocks public access and disables ACLs. It denies requests without TLS. It encrypts objects with an S3-managed key or, as an option, with a customer-managed KMS key. S3 Versioning keeps earlier databases for noncurrentVersionDays.
  • What readers see. By default, a Cost Explanation shows the minimal Billing Line, without tags and free-text names. The reason is that the readers of a Deployment can be a larger group than its billing administrators.

The policy pack checks these rules on every pull request. Each function's role is limited to the actions that its job requires, and the pack fails a role granted anything more. The local rules are in Security model.

What it costs

The expected scale is a few thousand to about a million Billing Lines a month. At this scale, a Deployment costs less than $1 a month in us-east-1 while the Lambda free tier covers it. These numbers are estimates from the published AWS prices, checked on 2026-11-06. They are not measurements:

Lambda, both functions (inside the free tier)$0.00$0.00
S3 storage and requestsabout $0.01about $0.29

Totalabout $0.01 to $0.06about $0.32 to $0.82
  • The estimates assume a daily collector run of 60 seconds (small) to 300 seconds, with the default 2 GB of memory of the collector. They also assume 10,000 API requests a month, each of 1 second at 1 GB, and a database of 0.1 GB to 12 GB.
  • Without Lambda's free tier, add about $0.18 (small) or $0.37 a month, which takes the larger case to about $1.20.
  • A customer-managed KMS key adds $1 a month.

AWS has no hard limit on spend, and a Budget cannot stop a function. Thus a Deployment limits its cost in these ways:

  • Each function has a timeout and a memory size.
  • The schedule runs one time each day, and a failed run gets two retries at most.
  • Logs expire. Inbox objects and old database versions also expire.
  • The optional Budget sends an email about forecast spend and actual spend.

If a problem still occurs, you can stop the API at once. See Read a Deployment.

Limits to watch

  • Each Collection Run moves the whole database in and out of S3. As it grows, so do the run's time and the API's cold start.
  • The /tmp of a function is the Lambda default of 512 MB, because the stack does not set a larger size yet. Thus today, the database must stay well below 512 MB. Lambda permits up to 10,240 MB, and one upload holds 5 GB at most.
  • Athena keeps query history for 45 days. If a Deployment stops collection for a longer time, it loses the history of that gap. The summary shows a warning when this can have occurred.
  • None of these is measured on a large account yet. Each is a revisit trigger in ADR 0026 or spec 08.
