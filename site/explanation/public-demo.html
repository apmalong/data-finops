    The Public Demo

    On this page

    • What is simulated and what is real
    • What is public
    • A static snapshot, not a live API
    • How fresh it is
    • What it costs

    The Public Demo shows the dashboard of a real Deployment, with data that is about one day old. Anyone can open it, without an account. This page explains what is simulated, what is real, what is public and how it stays fresh. The decisions are in ADR 0029 (the site), ADR 0030 (the workload) and ADR 0031 (Cost Dimensions). The design is in spec 09. These documents stay authoritative.

    Open the Public Demo: d1qumy1toc5b1v.cloudfront.net. It shows data only after the first Collection Run that finds the demo's charges in the bill.

    What is simulated and what is real

    Each banner of the demo says the same thing: "Simulated workload; real Athena charges, reconciled to the bill; data trails by about a day; amounts before credits".

    • Simulated: the orchestrator. There is no Airflow and no dbt. A scheduled Lambda function, the Simulated Orchestrator, plays both. Four times each day, it runs the DAGs that are due: daily_orders one time each day, hourly_events at each start and weekly_finance on Mondays. Each DAG has tasks, and each dbt task runs two to five models. Some tasks fail one time and succeed on the second try, and sometimes a run fails completely.
    • Simulated: the records. It writes OpenLineage events and dbt artifacts in the shapes that the Airflow OpenLineage provider, dbt-ol and dbt write. They are made from the real, anonymized records of the reference workload, and they go into the Inbox as a real producer puts them. Tests run them through the same readers as real input.
    • Simulated: the data and the people. The dataset of orders, customers and events is generated. The teams and tenants are fictional.
    • Real: the queries. Each model runs real SQL in a dedicated Athena workgroup, data-finops-demo. The first line of each query is the dbt-athena query comment, with the model's node_id, the run's invocation_id, and the team, tenant and DAG run. A failed model fails as in dbt: Athena fails its query.
    • Real: the bill. Athena charges for the scans. The charges arrive in the account's FOCUS export. A Collection Run then splits each Billing Line exactly among the queries in its scope, as for any other workgroup. The Identity Links to the Model Executions and DAG runs come from the same Evidence as for real dbt.

    The demo thus shows how data-finops works on a real bill. It is not evidence that real Airflow and dbt write these shapes. That evidence is the reference workload (ADR 0021).

    What is public

    The Deployment collects the FOCUS export of the whole account. Only the demo's part of it is published:

    • Only the Athena usage lines of the data-finops-demo workgroup, and what comes from them: their Allocations, Roll-ups, Cost Dimensions, lineage and Cost Explanations. A Snapshot Scope with none of these lines is not published.
    • Credit lines have no workgroup, so they are not published. The amounts are before credits.
    • Each 12-digit account ID becomes the example account, 123456789012.
    • Each Cost Explanation is the minimal one (ADR 0028). A Cost Dimension marked sensitive is not published.
    • Only the current and the previous Billing Periods are published.

    The rest of the owner's bill is never published.

    A static snapshot, not a live API

    A Deployment's API is private: IAM authorizes each request, and a browser cannot sign one. A public live API would put compute and the whole bill on the open internet. Thus the demo publishes files, and nothing public computes anything:

    1. The collector writes the database object after each Collection Run.
    2. S3 starts the publisher. It reads the database with the same read model as the API. It writes each answer that the dashboard can ask for as a JSON file, in the shape of the API. This set of files is a Demo Snapshot.
    3. The publisher writes each snapshot under a new prefix, then moves current.json to it. Thus a reader never sees half a snapshot. current.json moves only forward in time, so an older snapshot never replaces a newer one.
    4. CloudFront serves the dashboard's files and the snapshots from a private bucket. It redirects HTTP to HTTPS.

    The dashboard is the same dashboard that data-finops serve shows. On the demo, it reads the snapshot's files instead of the API. A view that the snapshot does not cover shows "not in the public demo". For example, a sensitive Cost Dimension, a Billing Period before the previous one, and a Workload Run that no published cost reaches are not published. Thus in the lineage of a DAG run, a task run that ran no charged query shows "not in the public demo".

    How fresh it is

    • The collector runs one time each day. The demo is as fresh as its last run.
    • AWS delivers the bill some hours after the usage. The newest queries are not published until their Billing Line arrives. Thus the demo trails by about a day.
    • The banner shows when the snapshot was published, and the Calculation Run of the Billing Period that the dashboard shows.
    • S3 deletes each snapshot after 30 days. If no snapshot is published for 30 days, the demo shows nothing.

    What it costs

    The target is about $3 a month or less. Athena costs about $1 to $2, because each query scans from less than 10 MB to some hundred MB. CloudFront, S3, Lambda, EventBridge and Glue stay in their free tiers at the traffic of a demo. A $10 Budget alert stays on. The real cost of one month is recorded when the demo has run for a month.

    To stop the demo, set publicDemo to false and run pulumi up. This removes the demo and its bucket. To stop only the queries, disable the schedule of the simulator. See Deploy to AWS.
