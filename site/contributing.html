    Contribute to data-finops

    On this page

    • Mutation tests

    This site is for people who run data-finops. The documents for people who build it live in the repository, where they stay authoritative:

    • AGENTS.md: how development works, and the engineering rules.
    • GLOSSARY.md: the domain language every page uses.
    • Specifications: what each part of data-finops must do.
    • Decision records: the architecture decisions and why they were made.
    • Plan: the milestones and their exit criteria.
    • Progress: how each milestone was verified.
    • Research: standards, reuse decisions and reviews.

    Tasks live in GitHub Issues. To change this site, edit the page in site/, then run python -m scripts.site build and python -m scripts.site check.

    To run all the checks of the repository, use python -m scripts.gates. The README tells you how to prepare the environments. The tests of the dashboard's static mode also need Node.

    Mutation tests

    Mutation tests measure the tests of the money path: the code that splits a Billing Line. A tool, mutmut, makes small changes to that code, one at a time. Each change is a mutant. A good test fails for each mutant. A mutant that no test finds is a survivor.

    The Mutation workflow in GitHub Actions runs mutmut each Monday. You can also start it from the Actions tab. It compares the score with the baseline in docs/implementation/mutation-baseline.json, and a lower score fails the run. The report of the run gives the score and lists each survivor.

    mutmut needs Linux, or WSL on Windows. To run it on your computer:

    uv sync --extra dev --extra api --extra aws --extra mutation
uv run mutmut run
uv run mutmut results --all true > mutation-results.txt
python -m scripts.mutation_score mutation-results.txt docs/implementation/mutation-baseline.json
    wsl
uv sync --extra dev --extra api --extra aws --extra mutation
uv run mutmut run
uv run mutmut results --all true > mutation-results.txt
python3 -m scripts.mutation_score mutation-results.txt docs/implementation/mutation-baseline.json

    The tests also need Node. A full run takes a long time, and mutmut keeps its work in mutants/. To see the change that a mutant makes, run uv run mutmut show NAME. For each survivor, add a test that kills it. If no test can kill it, record its name and the reason in the baseline.

    To check a page against the Simplified Technical English rules, run python -m scripts.ste_check site/contributing.html. The rules are in the simplified-technical-english skill. The pages in scripts/ste_converted.txt are a gate in CI.
