Serve with a token

On this page

  • Make a token
  • Serve with a token file
  • Serve with the token in the environment
  • Serve off loopback

serve runs the API, the dashboard and the OpenLineage receiver. On loopback, a token is optional. To serve on any other address, you need one. This guide sets a token and serves with it (ADR 0024).

Make a token

A token is at least 16 characters. Make a long random one and keep it in a file only you can read:

python -c "import secrets; print(secrets.token_urlsafe(32))" > finops.token
python -c "import secrets; print(secrets.token_urlsafe(32))" | Set-Content -Encoding ascii finops.token

This page uses fixtures/docs/example.token, which holds the dummy token example-token-not-a-secret. Never use it for a real server.

Serve with a token file

data-finops ingest focus fixtures/focus/export-2026-10.json --db finops.sqlite
data-finops serve --db finops.sqlite --token-file fixtures/docs/example.token
curl -s -H "Authorization: Bearer $(cat fixtures/docs/example.token)" http://127.0.0.1:8000/health
data-finops ingest focus fixtures/focus/export-2026-10.json --db finops.sqlite
data-finops serve --db finops.sqlite --token-file fixtures/docs/example.token
curl.exe -s -H "Authorization: Bearer $(cat fixtures/docs/example.token)" http://127.0.0.1:8000/health
focus: new aws-focus-123456789012-2026-10-v1
serving finops.sqlite at http://127.0.0.1:8000/ (Ctrl+C to stop)
{"status":"ok"}

$(cat …) puts the token in the header without writing it into the command, so with your own token, use $(cat finops.token). Every route now needs the header Authorization: Bearer <token>, the dashboard and the API documentation included. A request without it, or with another token, gets 401:

{"type":"about:blank","title":"Unauthorized","status":401,"detail":"A valid bearer token is required."}

An OpenLineage client sends the token as its API key, for example in OPENLINEAGE_API_KEY. See Receive OpenLineage events.

Serve with the token in the environment

Set DATA_FINOPS_TOKEN instead of passing --token-file:

export DATA_FINOPS_TOKEN="$(cat finops.token)"
data-finops serve --db finops.sqlite
$env:DATA_FINOPS_TOKEN = "$(cat finops.token)"
data-finops serve --db finops.sqlite

Not run on this page: pages run with no DATA_FINOPS_* settings.

Use the variable or a file, never both. With both, serve refuses to start:

data-finops: set the token in DATA_FINOPS_TOKEN or a file, not both

Serve off loopback

To accept requests from other machines, give --host with a token:

data-finops serve --db finops.sqlite --host 0.0.0.0 --token-file finops.token
data-finops serve --db finops.sqlite --host 0.0.0.0 --token-file finops.token

Without a token, serve refuses and exits with 2:

data-finops: refusing to serve on 0.0.0.0 without a token: set DATA_FINOPS_TOKEN or --token-file (ADR 0024)
  • Only a literal loopback address, such as 127.0.0.1 or ::1, counts as loopback. A name such as localhost needs a token too, because it could resolve to any address.
  • The token travels in plain text over HTTP. Off loopback, put the server behind TLS.
  • demo ignores any token. It always serves on loopback with every route open.

The token is never logged, printed or stored. The rules are listed in Exit codes and environment.
