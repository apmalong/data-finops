Ingest Athena query history

On this page

  • Fetch the history from AWS
  • Load it
  • Load overlapping history
  • What is kept

Athena's query history gives the Query Executions behind an Athena bill: how much each one scanned and, through its Trusted Query Comment, which Model Execution issued it. This guide fetches the history from AWS and loads it.

Fetch the history from AWS

List the Query Execution IDs of a workgroup, then fetch them with BatchGetQueryExecution, which takes at most 50 IDs per call:

aws athena list-query-executions --work-group <workgroup> --max-items 50 --output json
aws athena batch-get-query-execution --query-execution-ids <id> <id> … --output json > query-executions.json
aws athena list-query-executions --work-group <workgroup> --max-items 50 --output json
cmd /c "aws athena batch-get-query-execution --query-execution-ids <id> <id> … --output json > query-executions.json"

Not run on this page: it needs AWS credentials and an Athena workgroup.

Save the response as it is. In Windows PowerShell 5.1, > saves a file as UTF-16, which data-finops cannot read, so the Windows version saves it through cmd. data-finops reads the plain BatchGetQueryExecution response, up to 512 MiB per file.

Load it

The response does not say which account and Region it came from, so give them alongside it:

data-finops ingest athena fixtures/athena/query-executions.json --account-id 123456789012 --region us-east-1 --db finops.sqlite
data-finops ingest athena fixtures/athena/query-executions.json --account-id 123456789012 --region us-east-1 --db finops.sqlite
athena: 2 accepted, 0 duplicates, 0 changed copies, 0 rejected
  • duplicates: Query Executions already stored with the same content.
  • changed copies: a Query Execution already stored, reported again with different content. Both are kept, and the Query Execution is flagged as having conflicting observations.
  • rejected: an entry that fails validation. It is named by its position and the reason, never by its content. The rest is stored, and the command exits with 1.

A file that is not a BatchGetQueryExecution response prints athena: rejected: with the reason. Nothing from it is stored, and the command exits with 1.

Load overlapping history

Fetches often overlap. Loading the same history again stores nothing new:

data-finops ingest athena fixtures/athena/query-executions.json --account-id 123456789012 --region us-east-1 --db finops.sqlite
data-finops ingest athena fixtures/athena/query-executions.json --account-id 123456789012 --region us-east-1 --db finops.sqlite
athena: 0 accepted, 2 duplicates, 0 changed copies, 0 rejected

What is kept

Only allowlisted metadata is stored: identity, workgroup, statement type, catalog and database, state, times, error category and type, numeric statistics and engine version. Query text, execution parameters and error messages are dropped. From the Trusted Query Comment, only its invocation_id and node_id are kept. To send that comment, see Ingest dbt artifacts.
