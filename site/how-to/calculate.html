Calculate Allocations

This guide runs a Calculation Run. It splits every Billing Line of the current Export Snapshots into Allocations, and stores them as the current Allocation Snapshot of each Snapshot Scope.

Load the inputs first

A Calculation Run reads only what is stored when it starts. Load the Export Snapshot and the workload's Athena history, OpenLineage events and dbt artifacts first:

data-finops ingest focus fixtures/focus/export-2026-10.json --db finops.sqlite
data-finops ingest athena fixtures/athena/query-executions.json --account-id 123456789012 --region us-east-1 --db finops.sqlite
data-finops ingest openlineage fixtures/openlineage/events.json --db finops.sqlite
data-finops ingest dbt fixtures/dbt/manifest.json --db finops.sqlite
data-finops ingest dbt fixtures/dbt/run_results.json --db finops.sqlite

The how-to guides for FOCUS, Athena, OpenLineage and dbt explain each input.

Run the calculation

data-finops calculate --db finops.sqlite
calculate: 123456789012 2026-10-01 aws-data-exports:FOCUS_1_2_AWS: new calc-…

It prints one line for each Snapshot Scope: the billing account, the Billing Period, the source, the outcome and the Calculation Run's ID. new means a new Allocation Snapshot is stored and current.

Run it again

data-finops calculate --db finops.sqlite
calculate: 123456789012 2026-10-01 aws-data-exports:FOCUS_1_2_AWS: replay calc-…

With the same inputs and the same Allocation Policy, nothing new is stored, and the line names the current Calculation Run. Load new inputs and calculate again to change the Allocations. An event the HTTP receiver takes in changes no Allocation until the next calculate.

When there is nothing to calculate

  • A database file with no Export Snapshot prints calculate: no Export Snapshot to calculate and exits with 0.
  • A --db path with no database file there exits with 2.
