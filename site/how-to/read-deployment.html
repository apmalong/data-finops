Read a Deployment

On this page

  • Grant a reader access
  • Call the API
  • Open the dashboard on a local copy
  • Switch the API off

A Deployment's API serves the same read endpoints as data-finops serve, from the database the last Collection Run wrote. It sits behind a Function URL that accepts only requests signed with AWS Signature Version 4 (SigV4) by an IAM principal allowed to call it. There is no token. This guide grants that access, calls the API, opens the dashboard on a local copy and switches the API off when needed.

Not run on this page. These commands reach a real Deployment with your own AWS credentials. Attaching a policy needs an administrator, and the kill switch's pulumi up is owner-run.

Grant a reader access

The stack outputs readerPolicyArn, a managed policy that allows calling the API's Function URL and nothing else. Attach it to the role or user that will read, for example:

aws iam attach-role-policy --role-name <reader role> --policy-arn <readerPolicyArn> --profile <admin profile>
aws iam attach-role-policy --role-name <reader role> --policy-arn <readerPolicyArn> --profile <admin profile>

The policy allows both lambda:InvokeFunctionUrl and lambda:InvokeFunction, the second only through the Function URL. Function URLs created since October 2025 need both.

Call the API

A browser cannot sign SigV4, so use a client that can. awscurl signs with a named profile:

uv tool install awscurl
awscurl --service lambda --region <region> --profile <reader profile> "<apiUrl>health"
awscurl --service lambda --region <region> --profile <reader profile> "<apiUrl>v1/costs/summary"
uv tool install awscurl
awscurl --service lambda --region <region> --profile <reader profile> "<apiUrl>health"
awscurl --service lambda --region <region> --profile <reader profile> "<apiUrl>v1/costs/summary"

<apiUrl> is the stack output, which ends in /. curl 7.75 and later can sign too, with --aws-sigv4 "aws:amz:<region>:lambda" and the principal's keys. Every endpoint, parameter and response is in HTTP API, apart from POST /api/v1/lineage: a Deployment receives lineage through its Inbox, not over HTTP (Send workload metadata to the Inbox).

  • An unsigned request, or one from a principal not allowed to invoke the URL, gets 403 from AWS before data-finops sees it. The reader policy is one way to allow it; a principal with broader Lambda permissions, such as an administrator, is allowed too.
  • Before the first Collection Run there is no database yet, and every endpoint, /health included, answers 503.
  • A Cost Explanation shows the minimal Billing Line by default: its tags, free-text names and provider extension columns are withheld, and billing_line_detail says minimal (ADR 0028). Set explanationDetail to full to show the whole line. See Read a Cost Explanation.

Open the dashboard on a local copy

The dashboard is not served by a Deployment. Download the database the last Collection Run wrote, then serve it on your own machine:

aws s3 cp s3://<bucket>/database/data-finops.sqlite deployment.sqlite --profile <your profile>
data-finops serve --db deployment.sqlite
aws s3 cp s3://<bucket>/database/data-finops.sqlite deployment.sqlite --profile <your profile>
data-finops serve --db deployment.sqlite

The copy is a snapshot. Download it again for a later run's data. Downloading needs s3:GetObject on the database object, which neither output policy grants, and kms:Decrypt on the key when kmsKeyArn is set. serve shows the full Billing Line unless you pass --explanation-detail minimal.

Switch the API off

Setting the API function's reserved concurrency to 0 stops every request at once, without touching the data:

aws lambda put-function-concurrency --function-name <apiFunction> --reserved-concurrent-executions 0 --profile <your profile>
aws lambda put-function-concurrency --function-name <apiFunction> --reserved-concurrent-executions 0 --profile <your profile>

To keep it off through later deployments, record it in the stack too, then run pulumi up:

pulumi config set apiReservedConcurrency 0
pulumi config set apiReservedConcurrency 0

To switch the API back on, remove the setting with pulumi config rm apiReservedConcurrency and run pulumi up, or remove the reserved concurrency with aws lambda delete-function-concurrency.
