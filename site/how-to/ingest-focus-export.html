    Ingest a FOCUS export

    On this page

    • Load an Export Snapshot from a JSON file
    • Load it again safely
    • Load an AWS Data Exports Delivery
    • Collect Deliveries on a schedule
    • If the ingest is refused

    This guide loads an Export Snapshot into a database file: all the Billing Lines of one billing account, Billing Period and source, as the provider published them. It comes from a FOCUS JSON file or from an AWS Data Exports Delivery.

    Load an Export Snapshot from a JSON file

    data-finops ingest focus fixtures/focus/export-2026-10.json --db finops.sqlite
    data-finops ingest focus fixtures/focus/export-2026-10.json --db finops.sqlite
    focus: new aws-focus-123456789012-2026-10-v1

    The database file is created if it does not exist. The line gives the outcome, then the Export Snapshot's ID:

    • new: it is stored, and it is now the current Export Snapshot of its Snapshot Scope.
    • superseded: it is stored as a Superseded Snapshot, because a later publication of the same Snapshot Scope is current.
    • replay: nothing is stored, because the same content is already there.

    Load it again safely

    data-finops ingest focus fixtures/focus/export-2026-10.json --db finops.sqlite
    data-finops ingest focus fixtures/focus/export-2026-10.json --db finops.sqlite
    focus: replay aws-focus-123456789012-2026-10-v1

    A replay stores nothing, so you can run an ingest again and get no copies. Which Export Snapshot is current depends on the provider's publication time, never on the order you load them in (ADR 0020).

    Load an AWS Data Exports Delivery

    AWS Data Exports writes each Delivery as a manifest, <export>-Manifest.json, and its data files. Download both, then give ingest focus the manifest:

    data-finops ingest focus <download-dir>/<export>-Manifest.json --data-dir <data-files-dir> --db finops.sqlite
    data-finops ingest focus <download-dir>/<export>-Manifest.json --data-dir <data-files-dir> --db finops.sqlite

    Not run on this page: it requires a Delivery downloaded from AWS.

    • --data-dir names where the data files were downloaded. Leave it out when they are beside the manifest.
    • The publication time comes from the manifest, never from file times or the time you load it.

    Collect Deliveries on a schedule

    A Collection Run finds and loads Deliveries itself. Run one from your machine with data-finops collect, as Send workload metadata to the Inbox shows. A Deployment runs one every day. Set the export to create new files when it updates a period, in the Data Exports console. Each Delivery then has a folder of its own, and its publication time comes from that folder. A Collection Run refuses an export that overwrites its files, and shows a warning.

    For the billing_lookback_periods most recent Billing Periods (default 2, at most 24), a Collection Run does these steps:

    • It finds each Delivery whose two manifests are written. A Delivery that AWS still writes stays for a later run. A Delivery that a run took before is never downloaded again.
    • It loads each Delivery that is newer than the current Export Snapshot of its Snapshot Scope, oldest first. Thus the newest becomes current, and the others are kept as Superseded Snapshots.
    • It downloads only the data files that the manifest lists, and only from the folder of that Delivery in the export. If a manifest names a different file, data-finops rejects the manifest and does not read that file.
    • Before it downloads a file of a Delivery, it refuses the Delivery if its data files are more than 8 GiB together. It also refuses each data file over 2 GiB.

    A refused Delivery is named by its folder and the reason, and the run exits with 1.

    If the ingest is refused

    Nothing is stored, and the command exits with 2:

    • The file is not a FOCUS Export Snapshot, or the Delivery is not usable. The message names the file, never its content.
    • An Export Snapshot with the same ID is already stored with other content. Stored Export Snapshots never change.
