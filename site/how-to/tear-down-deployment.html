Tear down a Deployment

On this page

  • Before you destroy
  • Destroy and keep the data
  • Destroy and delete the data
  • What is left

pulumi destroy removes a Deployment. By default it keeps the bucket, with the database and the Inbox in it, so a mistaken destroy loses no data. This guide removes a Deployment either way and lists what is left behind.

Not run on this page. These commands reach a real AWS account, and some create resources that cost money. The account owner approves every pulumi preview, pulumi up and pulumi destroy against a real account.

Before you destroy

Detach the producer and reader policies from every identity they were attached to. IAM refuses to delete a managed policy that is still attached, and the destroy stops there:

aws iam list-entities-for-policy --policy-arn <producerPolicyArn> --profile <admin profile>
aws iam list-entities-for-policy --policy-arn <readerPolicyArn> --profile <admin profile>
aws iam detach-role-policy --role-name <role> --policy-arn <policy arn> --profile <admin profile>
aws iam list-entities-for-policy --policy-arn <producerPolicyArn> --profile <admin profile>
aws iam list-entities-for-policy --policy-arn <readerPolicyArn> --profile <admin profile>
aws iam detach-role-policy --role-name <role> --policy-arn <policy arn> --profile <admin profile>

Run every command below from infra/pulumi/aws, with PULUMI_BACKEND_URL and PULUMI_CONFIG_PASSPHRASE set as in Deploy to AWS.

Destroy and keep the data

pulumi destroy
pulumi destroy

This deletes the functions, their log groups and roles, the schedule, the Function URL, the producer and reader policies, the alarm and its topic, the Budget, and the Lambda package object. It keeps the bucket and every setting on it: the public access blocks, encryption, versioning, the expiry rules and the TLS-only policy. The bucket leaves the stack's state, so a later pulumi up would try to create a new bucket with a new name, not adopt this one.

While the bucket is kept, its storage is billed and its expiry rules keep running: Inbox objects expire after inboxRetentionDays and old object versions after noncurrentVersionDays. To delete it later, empty it in the S3 console, which deletes every version, then delete it.

Destroy and delete the data

To delete the bucket with everything in it, every version included, change the setting and apply it first. The stack records whether to keep the bucket when it is deployed, not when it is destroyed:

pulumi config set deleteDataOnDestroy true
pulumi up
pulumi destroy
pulumi config set deleteDataOnDestroy true
pulumi up
pulumi destroy

This cannot be undone. Download the database first if you may want it: see Read a Deployment.

What is left

  • The stack's local state, in .local/pulumi. Remove the empty stack with pulumi stack rm dev.
  • The package, infra/pulumi/aws/build/data-finops-lambda.zip, which is git-ignored.
  • The deployer identity and its profile, which the owner created and removes.
  • Anything a producer or reader set up on its own side, such as an OpenLineage configuration that writes to the Inbox.
  • The FOCUS export and the Athena workgroups, which the Deployment only read.

The reference workload is a separate stack with its own teardown: see Deploy the reference workload.
