Handle a restated export

On this page

  • Start from a calculated bill
  • Load the restated Export Snapshot and recalculate
  • Check that the new Calculation Run is current
  • An older Export Snapshot loaded late

A provider can publish a Billing Period again with changed Billing Lines. This guide loads the restated Export Snapshot and recalculates. Nothing earlier is overwritten.

Start from a calculated bill

data-finops ingest focus fixtures/focus/export-2026-10.json --db finops.sqlite
data-finops calculate --db finops.sqlite
data-finops serve --db finops.sqlite
data-finops ingest focus fixtures/focus/export-2026-10.json --db finops.sqlite
data-finops calculate --db finops.sqlite
data-finops serve --db finops.sqlite
focus: new aws-focus-123456789012-2026-10-v1
calculate: 123456789012 2026-10-01 aws-data-exports:FOCUS_1_2_AWS: new calc-…
serving finops.sqlite at http://127.0.0.1:8000/ (Ctrl+C to stop)

serve keeps running, so run the rest in a second terminal.

Load the restated Export Snapshot and recalculate

data-finops ingest focus fixtures/focus/export-2026-10-restated.json --db finops.sqlite
data-finops calculate --db finops.sqlite
data-finops ingest focus fixtures/focus/export-2026-10-restated.json --db finops.sqlite
data-finops calculate --db finops.sqlite
focus: new aws-focus-123456789012-2026-10-v2
calculate: 123456789012 2026-10-01 aws-data-exports:FOCUS_1_2_AWS: new calc-…

The restated Export Snapshot is published later, so it is now current. The earlier one becomes a Superseded Snapshot and is kept. A restatement replaces the whole Export Snapshot, never single Billing Lines (ADR 0015).

Check that the new Calculation Run is current

Set CALCULATION_RUN_ID to the ID the last calculate printed:

CALCULATION_RUN_ID=calc-<the ID calculate printed>
CALCULATION_RUN_ID=calc-<the ID calculate printed>
curl -s "http://127.0.0.1:8000/v1/provenance?calculation_run_id=$CALCULATION_RUN_ID"
curl.exe -s "http://127.0.0.1:8000/v1/provenance?calculation_run_id=$CALCULATION_RUN_ID"
{"calculation_run_id":"calc-…",…"is_current":true,"superseded_by":null,"export_snapshot":{"snapshot_id":"aws-focus-123456789012-2026-10-v2",…

Ask for the first Calculation Run's ID the same way: it answers "is_current":false, and superseded_by names the new run. Its Allocation Snapshot is kept as history.

An older Export Snapshot loaded late

Exports can arrive out of order. Into a new database file, load the restated Export Snapshot first, then the earlier one:

data-finops ingest focus fixtures/focus/export-2026-10-restated.json --db late.sqlite
data-finops ingest focus fixtures/focus/export-2026-10.json --db late.sqlite
data-finops ingest focus fixtures/focus/export-2026-10-restated.json --db late.sqlite
data-finops ingest focus fixtures/focus/export-2026-10.json --db late.sqlite
focus: new aws-focus-123456789012-2026-10-v2
focus: superseded aws-focus-123456789012-2026-10-v1

The earlier publication is stored as a Superseded Snapshot, and the latest publication stays current, whatever the order of loading (ADR 0020). Loading an Export Snapshot that is already stored prints replay and stores nothing.
