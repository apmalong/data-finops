Read a Cost Explanation

A Cost Explanation shows why one Allocation got its amount: the Billing Line it came from, the Allocation, its Evidence and the Roll-ups it adds to. This guide finds an Allocation through the API and reads its Cost Explanation (spec 06).

Calculate and serve

Load a bill and its workload, then calculate:

data-finops ingest focus fixtures/focus/export-2026-10.json --db finops.sqlite
data-finops ingest athena fixtures/athena/query-executions.json --account-id 123456789012 --region us-east-1 --db finops.sqlite
data-finops ingest openlineage fixtures/openlineage/events.json --db finops.sqlite
data-finops ingest dbt fixtures/dbt/manifest.json --db finops.sqlite
data-finops ingest dbt fixtures/dbt/run_results.json --db finops.sqlite
data-finops calculate --db finops.sqlite
data-finops serve --db finops.sqlite
calculate: 123456789012 2026-10-01 aws-data-exports:FOCUS_1_2_AWS: new calc-…
serving finops.sqlite at http://127.0.0.1:8000/ (Ctrl+C to stop)

serve keeps running, so run the rest in a second terminal. Set CALCULATION_RUN_ID to the ID calculate printed:

CALCULATION_RUN_ID=calc-<the ID calculate printed>

Find the Allocation

List the Calculation Run's direct Allocations:

curl -s "http://127.0.0.1:8000/v1/allocations?calculation_run_id=$CALCULATION_RUN_ID&cost_basis=BilledCost&category=direct"
{"calculation_run_id":"calc-…","total":1,…"items":[{"ref":"calc-…#0","allocation":{…"target_type":"query_execution","target_id":"q-001","amount":"6.00",…

Each item's ref addresses one Allocation as <calculation_run_id>#<position>. This one gives $6.00 to Query Execution q-001.

Read its Cost Explanation

Ask for /v1/allocations/<ref>/explanation, sending the # as %23:

curl -s "http://127.0.0.1:8000/v1/allocations/$CALCULATION_RUN_ID%230/explanation"
{"ref":"calc-…#0","billing_line_ref":"aws-focus-123456789012-2026-10-v1#0","billing_line":{"BilledCost":"6.00",…"ServiceName":"Amazon Athena",…"allocation":{…"category":"direct","method":"estimated_metered_share","confidence":"metered_estimate","coverage":"1",…"query_execution":{…"query_execution_id":"q-001",…"model_execution":{"invocation_id":"inv-001","node_id":"model.demo.orders",…"workload_runs":[{"run_id":"00000000-0000-4000-8000-000000000002",…"rollups":[{"level":"model_execution",…"amount":"6.00"}…

Read it in order:

  1. billing_line: the Billing Line exactly as exported, every FOCUS column included.
  2. allocation: its Allocation Category, method, Confidence, Coverage, Allocation Policy version and Calculation Run.
  3. The Evidence, each reference resolved: query_execution, then model_execution with its dbt Node, then workload_runs, nearest first. A Workload Run known only as another's parent or root shows "run":null.
  4. rollups: each Roll-up the Allocation adds to, in its currency and Cost Basis.

For an Unallocated Allocation, unallocated_reason says why it is Unallocated, such as ineligible. The dashboard shows the same Cost Explanation when you click an Allocation.
