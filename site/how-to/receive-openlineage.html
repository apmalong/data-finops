Receive OpenLineage events

On this page

  • Load events from a file
  • Receive events over HTTP
  • Point an OpenLineage client at it

OpenLineage RunEvents tell data-finops about Workload Runs: an Airflow DAG run, the dbt run inside it, and how they nest. This guide loads them from a file, then receives them over HTTP.

Load events from a file

The file holds a JSON array of events, or one event per line (JSON Lines):

data-finops ingest openlineage fixtures/openlineage/events.json --db finops.sqlite
openlineage: 5 accepted, 0 duplicates, 0 changed copies, 0 unsupported, 0 rejected
  • duplicates: events already stored with the same content. Loading the file again stores nothing.
  • changed copies: an event already stored, reported again with different content. Both are kept.
  • unsupported: a JobEvent or DatasetEvent, which data-finops does not read. These do not change the exit code.
  • rejected: an event that is not a valid RunEvent. The rest of the file is stored, and the command exits with 1.

Each unsupported or rejected event is named by its position and the reason, never by its content. For example:

openlineage: 3 accepted, 0 duplicates, 0 changed copies, 2 unsupported, 4 rejected
  2: not valid JSON
  3: invalid RunEvent: run/runId (format)
  4: invalid RunEvent: eventTime (format)
  5: invalid ParentRunFacet: (event) (required)
  6: unsupported JobEvent
  7: unsupported DatasetEvent

Receive events over HTTP

serve also runs the receiver, at POST /api/v1/lineage, the default endpoint of OpenLineage's HTTP transport. Each request carries one event:

data-finops serve --db finops.sqlite
curl -s -X POST -H 'Content-Type: application/json' --data-binary @fixtures/openlineage/one-event.json http://127.0.0.1:8000/api/v1/lineage
serving finops.sqlite at http://127.0.0.1:8000/ (Ctrl+C to stop)
{"accepted":1,"duplicates":0,"changed_copies":0}

serve keeps running, so send events from a second terminal. The receiver screens each event exactly as it screens one item of a file:

  • 201 with the counts above when the event is stored, or was already there.
  • 202 for an unsupported event, which is not stored.
  • 400 for a rejected event, with the reason.
  • 413 for a body over the 1 MiB event cap. It is refused before it is read in full.
  • 415 for a compressed body. Send each event uncompressed.

A received event changes no Allocation until the next calculate.

Point an OpenLineage client at it

For an OpenLineage client that reads its settings from the environment, such as the Python client that Airflow and dbt use:

OPENLINEAGE_URL=http://127.0.0.1:8000
OPENLINEAGE_ENDPOINT=api/v1/lineage

Not run on this page: it configures a client outside data-finops.

To receive events from another machine, serve needs a token, which the client sends as its API key. See Serve with a token.
